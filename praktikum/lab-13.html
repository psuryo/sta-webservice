LAB 13

Deployment Microservices (Docker Compose / Edge)

Mengemas setiap service toko ke dalam container, menjalankan seluruh sistem (gateway, dua service, RabbitMQ, consumer) dengan satu perintah memakai Docker Compose, lalu menguji hasil kemasan itu dengan test dan CI dari lab 12.

Durasi maks. 2 jam
Format Praktikum Berkelompok
Prasyarat Lab 09, 10, 12 (hasil toko + test + CI), Docker Desktop dengan Compose v2
Kaitan dengan lab sebelumnya dan proyek: Selama ini setiap service dijalankan manual di terminal terpisah dengan alamat localhost. Di Compose, tiap service punya nama dan menemukan service lain lewat nama itu (contoh nyata dari service discovery di kuliah). Test dan workflow CI dari lab 12 dipakai kembali, sehingga yang diuji adalah sistem yang benar-benar dikemas, bukan sekadar kode di laptop. Hasil lab ini adalah fondasi untuk persiapan proyek akhir di lab 14.
Tujuan Pembelajaran
  • 01Mahasiswa mampu membuat Dockerfile untuk service Node.js dan memahami isinya.
  • 02Mahasiswa mampu menggambarkan seluruh sistem dalam satu docker-compose.yml, termasuk jaringan, health check, dan urutan start.
  • 03Mahasiswa mampu memindahkan konfigurasi (alamat service, URL broker) dari kode ke environment variable.
  • 04Mahasiswa mampu menjalankan test dan CI terhadap stack Compose, serta mengamati perilaku sistem saat satu service dihentikan.
Gambaran Arsitektur

Dari Banyak Terminal ke Satu Perintah

SEBELUM: 5 terminal, alamat localhost, urutan start diingat manual SESUDAH: docker compose up --build host :8080 ──▶ [gateway] ──▶ [product-service] http://product-service:3000 │ ▲ └──▶ [order-service] ──▶ [rabbitmq] ──▶ [notification-service] http://order-service:3001 amqp://rabbitmq Hanya gateway (:8080) dan dashboard RabbitMQ (:15672) dibuka ke host. Service saling menemukan lewat nama di jaringan Compose.

Port 3000 dan 3001 tidak perlu dibuka ke host: klien hanya boleh masuk lewat gateway, sama seperti pada sistem produksi.

Langkah Praktik

Mengemas dan Menjalankan Seluruh Sistem

01

Pindahkan Konfigurasi ke Environment

Hentikan semua service yang masih berjalan manual (Ctrl+C) agar port tidak bentrok. Di dalam container, localhost berarti container itu sendiri, jadi alamat service lain tidak boleh di-hard-code. Order-service dan notification-service sudah membaca PRODUCT_SERVICE_URL dan AMQP_URL dari environment. Sesuaikan gateway: pada gateway.js, cari nilai target pada kedua rute proxy dan ganti dengan variabel berikut:

const PRODUCT_SERVICE_URL = process.env.PRODUCT_SERVICE_URL || 'http://localhost:3000'; const ORDER_SERVICE_URL = process.env.ORDER_SERVICE_URL || 'http://localhost:3001'; // lalu: target: PRODUCT_SERVICE_URL (rute /product-service) // target: ORDER_SERVICE_URL (rute /order-service)

Pastikan ketiga service dan gateway tetap bisa dijalankan manual seperti sebelumnya (nilai bawaan localhost dipertahankan).

02

Buat Dockerfile dan .dockerignore

Di folder product-service, buat Dockerfile:

FROM node:22-alpine WORKDIR /app ENV NODE_ENV=production COPY package*.json ./ RUN npm ci --omit=dev # lapisan ini di-cache selama package*.json tidak berubah COPY . . USER node # jangan jalankan sebagai root EXPOSE 3000 CMD ["node", "product-service.js"]

Buat juga .dockerignore berisi node_modules, .git, npm-debug.log, dan .env agar folder lokal tidak ikut tersalin. Ulangi untuk service lain dengan perbedaan berikut (isi lainnya sama):

  • order-service: EXPOSE 3001, CMD ["node", "order-service.js"]
  • notification-service: tanpa EXPOSE (hanya consumer), CMD ["node", "notification-service.js"]
  • gateway: EXPOSE 8080, CMD ["node", "gateway.js"]

Pastikan package-lock.json ada di tiap folder (dari lab 12). Salinan .dockerignore yang sama dipakai di keempat folder.

03

Tulis docker-compose.yml

Di akar repository (sejajar dengan keempat folder service), buat docker-compose.yml:

services: rabbitmq: image: rabbitmq:3-management ports: - "15672:15672" healthcheck: test: ["CMD", "rabbitmq-diagnostics", "-q", "ping"] interval: 10s timeout: 5s retries: 10 start_period: 20s product-service: build: ./product-service restart: unless-stopped healthcheck: test: ["CMD", "wget", "-qO-", "http://localhost:3000/health"] interval: 10s timeout: 3s retries: 5 start_period: 5s order-service: build: ./order-service restart: unless-stopped environment: PRODUCT_SERVICE_URL: http://product-service:3000 AMQP_URL: amqp://rabbitmq depends_on: product-service: condition: service_healthy rabbitmq: condition: service_healthy healthcheck: test: ["CMD", "wget", "-qO-", "http://localhost:3001/health"] interval: 10s timeout: 3s retries: 5 start_period: 5s notification-service: build: ./notification-service restart: unless-stopped environment: AMQP_URL: amqp://rabbitmq depends_on: rabbitmq: condition: service_healthy gateway: build: ./gateway restart: unless-stopped ports: - "8080:8080" environment: PRODUCT_SERVICE_URL: http://product-service:3000 ORDER_SERVICE_URL: http://order-service:3001 PRODUCT_DOC_URL: http://product-service:3000/openapi.json ORDER_DOC_URL: http://order-service:3001/openapi.json depends_on: product-service: condition: service_healthy order-service: condition: service_healthy healthcheck: test: ["CMD", "wget", "-qO-", "http://localhost:8080/health"] interval: 10s timeout: 3s retries: 5 start_period: 5s

Perhatikan tiga hal: alamat antar service memakai nama service, hanya gateway dan dashboard yang punya ports, dan depends_on dengan service_healthy memastikan urutan start berdasarkan kesiapan, bukan sekadar "sudah menyala". Variabel PRODUCT_DOC_URL dan ORDER_DOC_URL hanya terpakai bila Anda mengerjakan lab 11; menyertakannya tidak berbahaya.

04

Jalankan dan Uji Stack

docker compose up --build # build pertama butuh beberapa menit

Di terminal lain (tetap di akar repository):

docker compose ps # semua service harus Up, yang punya healthcheck "healthy" npm test # test lab 12 terhadap gateway :8080

Semua test harus lulus tanpa mengubah satu baris pun, karena gateway tetap di localhost:8080. Buka http://localhost:15672 untuk dashboard RabbitMQ, dan lihat log beberapa service sekaligus dengan docker compose logs order-service product-service notification-service. Cari id yang sama pada log kedua service (pelacakan dari lab 12) dan baris "email terkirim" dari notification-service.

05

Latihan Kegagalan di Compose

  • docker compose stop product-service, lalu kirim POST /order-service/orders lewat gateway: hasilnya 503. Jalankan docker compose ps dan catat status order-service dan gateway.
  • docker compose start product-service, tunggu statusnya healthy, lalu kirim order lagi: harus 201.
  • Ubah satu hal kecil di kode order-service (misalnya teks pesan error) dan jalankan docker compose up -d tanpa --build: perubahan tidak muncul. Ulangi dengan docker compose up -d --build order-service: perubahan muncul. Container berisi salinan kode saat build, bukan folder Anda.
  • docker compose down lalu docker compose up -d: stok dan pesanan kembali ke data awal karena data hanya ada di memori container.
06

Perbarui Workflow CI agar Memakai Compose

Ganti isi .github/workflows/ci.yml dari lab 12. Kini CI membangun image dan menjalankan stack yang sama dengan yang Anda pakai, bukan menyalakan service satu per satu:

name: CI on: [push, pull_request] jobs: test: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-node@v4 with: node-version: 22 - name: Build dan nyalakan stack run: docker compose up -d --build --wait - name: Run tests run: npm test - name: Tampilkan log if: always() run: docker compose logs - name: Matikan stack if: always() run: docker compose down -v

Opsi --wait membuat perintah menunggu sampai service sehat dan gagal bila ada yang tidak sehat. Commit dan push ke main; run di tab Actions harus hijau.

07

Perbarui README, Commit & Bukti

Tambahkan bagian Menjalankan dengan Docker Compose pada README.md: prasyarat (Docker), perintah docker compose up --build, alamat penting (:8080, :8080/docs bila ada, :15672), cara menjalankan test, dan cara mematikan (docker compose down). Commit seluruh perubahan (Dockerfile dan .dockerignore tiap service, docker-compose.yml, ci.yml, README) tanpa node_modules dan tanpa kredensial.

Pengayaan (tidak dinilai wajib)

Ke cloud dan ke edge. Image yang sama dapat dideploy ke platform seperti Render sebagai Docker web service, dengan environment variable untuk alamat antar service dan /health sebagai health check. Gateway juga dapat dipindah ke edge (Cloudflare Workers) dengan service di Render sebagai origin. Perhatikan: layanan gratis dapat tertidur saat idle sehingga request pertama lambat dan bisa melewati timeout 2 detik di order-service, serta data di memori hilang saat restart. Syarat dan antarmuka platform berubah, jadi ikuti dokumentasi terbaru masing-masing.

Kesalahan Umum
Masalah yang Sering Muncul
Cannot connect to the Docker daemon

Docker Desktop belum berjalan. Nyalakan dan tunggu sampai statusnya siap, lalu ulangi.

port is already allocated / address already in use (8080, 15672)

Service manual atau container RabbitMQ dari lab 10 masih berjalan. Hentikan terminal lama dan jalankan docker rm -f rabbit.

Gateway membalas 502/ECONNREFUSED ke localhost:3000

Target proxy di gateway.js masih di-hard-code ke localhost. Pakai variabel environment (langkah 01) lalu build ulang dengan --build.

ECONNREFUSED 127.0.0.1:5672 di log order-service atau notification-service

Nilai AMQP_URL belum terbaca dari environment, atau service dijalankan sebelum RabbitMQ siap. Periksa environment dan depends_on di compose.

Service berstatus unhealthy / dependency failed to start

Endpoint /health belum ada (lab 12 langkah 04) atau port di healthcheck tidak sama dengan port aplikasi. Lihat docker compose logs nama-service.

npm ci gagal saat build image

package-lock.json tidak ada di folder service atau tidak sinkron dengan package.json. Jalankan npm install lokal lalu commit lock-nya.

Perubahan kode tidak muncul setelah docker compose up

Image tidak dibangun ulang. Tambahkan --build atau docker compose build lebih dulu.

CI merah di langkah "Build dan nyalakan stack"

Buka log langkah itu dan langkah "Tampilkan log". Penyebab umum: file tidak ter-commit, huruf besar/kecil nama file berbeda (Linux membedakan), atau service tidak sehat.

Checklist Kesiapan
  • Gateway membaca alamat service dari environment variable, tetap bisa berjalan manual
  • Keempat service punya Dockerfile dan .dockerignore
  • docker compose up --build menjalankan seluruh sistem dan docker compose ps menunjukkan semuanya sehat
  • Hanya gateway dan dashboard RabbitMQ yang dibuka ke host
  • npm test lulus terhadap stack Compose tanpa mengubah test
  • Saat product-service dihentikan: order 503; setelah dinyalakan kembali: 201
  • Workflow CI memakai Compose dan hijau pada main
  • README menjelaskan cara menjalankan dengan Compose; tidak ada kredensial atau node_modules di repository
