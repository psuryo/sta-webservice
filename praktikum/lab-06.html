LAB 06

Service dengan gRPC & Protocol Buffers

Mengimplementasikan file .proto yang sudah divalidasi sebagai tugas kuliah sesi 6 — kali ini benar-benar dijalankan sebagai gRPC server yang terhubung ke database Neon.

Durasi 100 menit
Format Praktikum Berkelompok
Terkait Kuliah Sesi 06 — gRPC & Protocol Buffers
Kaitan dengan kuliah: Gunakan file .proto yang sudah Anda tulis dan validasi sebagai tugas mandiri sesi 6 sebagai titik awal. Anda tidak perlu install protoc terpisah — library @grpc/proto-loader yang dipakai di lab ini bisa membaca file .proto langsung saat runtime, tanpa proses compile manual.
Tujuan Pembelajaran
  • 01Mahasiswa mampu menjalankan gRPC server di Node.js berdasarkan file .proto yang sudah dibuat sendiri.
  • 02Mahasiswa mampu menghubungkan method gRPC ke database Neon yang sama dipakai di lab-lab sebelumnya.
  • 03Mahasiswa mampu menguji service gRPC menggunakan gRPC client di Postman.
  • 04Mahasiswa mampu men-deploy gRPC server ke Render dan mengaksesnya lewat alamat publik.
Alat yang Dibutuhkan

Tools Praktikum

Node.js + @grpc/grpc-js wajib
Library resmi gRPC untuk Node.js — menjalankan server dan menangani komunikasi biner.
@grpc/proto-loader wajib
Membaca file .proto langsung saat runtime, tanpa perlu tahap compile terpisah dengan protoc.
Paket pg (dari lab 04) wajib
Driver PostgreSQL yang sama, dipakai method gRPC untuk mengambil data dari Neon.
Postman (gRPC client) wajib
Postman mendukung request gRPC secara native — tinggal muat file .proto, tidak perlu tool terpisah seperti grpcurl.
Langkah Praktik

Membangun & Men-deploy gRPC Server

01

Instal Dependensi

# bisa dalam folder proyek baru, atau proyek Node.js yang sudah ada npm install @grpc/grpc-js @grpc/proto-loader pg dotenv
02

Siapkan File .proto

Salin file .proto dari tugas kuliah sesi 6 ke folder proyek (mis. product.proto). Sesuaikan message di dalamnya supaya field-nya cocok dengan tabel Neon yang sudah Anda buat di lab 03:

// product.proto syntax = "proto3"; message Product { int32 id = 1; string title = 2; float price = 3; } message ProductRequest { int32 id = 1; } service ProductService { rpc GetProduct(ProductRequest) returns (Product); }
03

Muat .proto & Implementasikan Method

Alih-alih generate kode statis, muat definisi service langsung dari file .proto, lalu implementasikan method-nya supaya mengambil data nyata dari Neon:

const grpc = require('@grpc/grpc-js'); const protoLoader = require('@grpc/proto-loader'); const { Pool } = require('pg'); const pool = new Pool({ connectionString: process.env.DATABASE_URL }); const packageDef = protoLoader.loadSync('product.proto'); const proto = grpc.loadPackageDefinition(packageDef); const server = new grpc.Server(); server.addService(proto.ProductService.service, { GetProduct: async (call, callback) => { const result = await pool.query( 'SELECT * FROM products WHERE id = $1', [call.request.id] ); const row = result.rows[0]; callback(null, { id: row.id, title: row.title, price: row.price }); } }); server.bindAsync( \`0.0.0.0:${process.env.PORT || 50051}\`, grpc.ServerCredentials.createInsecure(), () => console.log('gRPC server berjalan') );
04

Uji Lokal Lewat Postman

Buka Postman, buat request baru bertipe gRPC, isi alamat localhost:50051, muat file product.proto sebagai service definition, pilih method GetProduct, isi id yang valid, lalu kirim. Periksa response yang kembali berisi data produk asli dari Neon.

05

Deploy ke Render

Push kode ke GitHub, buat "New Web Service" di Render, hubungkan repository, tambahkan environment variable DATABASE_URL (connection string Neon yang sama). Render akan otomatis meneruskan trafik HTTP/2 yang dibutuhkan gRPC ke port yang di-bind server Anda.

06

Uji Ulang Lewat URL Publik

Di Postman, ganti alamat server dari localhost:50051 ke alamat Render (mis. nama-app.onrender.com:443), aktifkan TLS di pengaturan request, lalu jalankan method yang sama untuk memastikan gRPC server bisa diakses publik.

Checklist Kesiapan
  • gRPC server berhasil dijalankan lokal berdasarkan file .proto sendiri (bukan contoh modul)
  • Method gRPC benar-benar mengambil data dari Neon, bukan data hardcode
  • Request berhasil dijalankan lewat gRPC client Postman, baik lokal maupun lewat URL Render
  • Response yang diterima sesuai dengan struktur message yang didefinisikan di .proto
