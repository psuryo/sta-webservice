LAB 02

Demo Singkat SOAP: Eksplorasi Request/Response & WSDL Siap Pakai

Bukan membangun SOAP service dari nol — cukup mengeksplorasi WSDL yang sudah ada dan merasakan langsung bentuk request/response SOAP, sebagai pelengkap konsep yang dibahas di kuliah sesi 3.

Durasi 100 menit
Format Praktikum Mandiri/Berpasangan
Terkait Kuliah Sesi 03 — SOA & SOAP
Kaitan dengan kuliah: Sesi 03 kuliah membahas anatomi SOAP (envelope, header, body) dan WSDL sebagai contract-first secara konseptual. Lab ini memberi pengalaman langsung membaca WSDL nyata dan mengirim request SOAP — cukup untuk membentuk intuisi, tanpa perlu membangun service SOAP sendiri.
Tujuan Pembelajaran
  • 01Mahasiswa mampu membaca dokumen WSDL milik layanan SOAP publik dan mengidentifikasi operasi yang tersedia.
  • 02Mahasiswa mampu menyusun dan mengirim SOAP request menggunakan Postman.
  • 03Mahasiswa mampu membaca struktur SOAP response dan menemukan data hasil di dalamnya.
  • 04Mahasiswa mampu membandingkan pengalaman memakai SOAP dengan REST secara langsung, bukan cuma secara teori.
Alat yang Dibutuhkan

Tools Praktikum

Postman wajib
Dipakai untuk mengirim SOAP request sebagai raw XML lewat HTTP POST — tidak perlu tools khusus SOAP.
Browser wajib
Untuk membuka dan membaca dokumen WSDL layanan demo langsung dari URL-nya.
Catatan Ketersediaan Layanan Demo Lab ini memakai layanan SOAP publik gratis (Number Conversion Service milik DataAccess) sebagai contoh. Layanan publik semacam ini kadang tidak stabil — jika tidak bisa diakses, dosen akan menyediakan WSDL alternatif atau file WSDL cadangan sebelum sesi dimulai.
Langkah Praktik

Eksplorasi WSDL & Kirim Request

01

Buka Dokumen WSDL

Akses WSDL Number Conversion Service lewat browser: https://www.dataaccess.com/webservicesserver/NumberConversion.wso?WSDL. Cari bagian <portType> dan <message> — identifikasi nama operasi dan parameter yang dibutuhkan.

02

Susun SOAP Request di Postman

Buat request baru: method POST, header Content-Type: text/xml; charset=utf-8, lalu isi body (raw, XML) dengan envelope SOAP berikut:

<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/"> <soap:Body> <NumberToWords xmlns="http://www.dataaccess.com/webservicesserver/"> <ubiNum>500</ubiNum> </NumberToWords> </soap:Body> </soap:Envelope>
03

Kirim & Periksa Response

Klik Send, lalu amati struktur XML response yang kembali. Temukan bagian <soap:Body> dan cari nilai hasil konversinya (misalnya angka 500 akan diubah menjadi teks "five hundred").

04

Refleksi: Bandingkan dengan REST/JSON

Bandingkan pengalaman ini dengan REST API berbasis JSON yang sudah biasa Anda pakai di mata kuliah Backend Programming. Perhatikan: ukuran payload XML vs JSON untuk data yang sama, dan seberapa mudah membaca strukturnya sekilas.

Checklist Kesiapan
  • Berhasil membuka dan membaca dokumen WSDL layanan demo
  • Berhasil mengirim SOAP request lewat Postman dan mendapat response 200
  • Berhasil menemukan nilai hasil di dalam SOAP response
  • Sudah menuliskan minimal 3 poin perbandingan SOAP/XML vs REST/JSON dari pengalaman langsung
  • Aplikasi kecil berhasil menerima input, mengirim SOAP request, dan menampilkan hasil konversi
Tugas & Latihan
Latihan Mandiri: Bangun Aplikasi Kecil

Setelah berhasil mengirim request lewat Postman, buat aplikasi kecil (boleh CLI script atau halaman sederhana) yang mengonsumsi operasi NumberToWords dari service ini:

  • Menerima input angka dari pengguna (lewat argumen command line, form input, atau prompt sederhana).
  • Menyusun SOAP envelope secara terprogram (bukan hardcode), lalu mengirimkannya lewat HTTP POST ke endpoint service.
  • Mem-parsing XML response dan menampilkan hasil konversinya ke pengguna dalam bentuk yang mudah dibaca.

Catatan teknis: gunakan bahasa/runtime sisi server (Python, Node.js, atau bahasa lain yang biasa dipakai di Backend Programming) — bukan JavaScript langsung di browser, karena layanan ini tidak menyediakan header CORS sehingga request dari browser kemungkinan akan diblokir. Sertakan juga refleksi singkat (3-5 kalimat): apa yang terasa lebih rumit saat membangun aplikasi nyata di atas SOAP dibanding kalau memakai REST/JSON. Kumpulkan kode dan refleksinya sebelum lab 03.
