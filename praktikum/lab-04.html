LAB 04

GraphQL API Sederhana (Render + Neon)

Mengimplementasikan kontrak yang sudah dirancang di lab 03 — kali ini dalam bentuk GraphQL server sungguhan yang terhubung ke database Neon milik kelompok Anda sendiri, dengan minimal dua tabel yang saling berelasi, lalu di-deploy ke Render.

Durasi 100 menit
Format Praktikum Berkelompok
Terkait Lab 03 — Skema Neon & OpenAPI
Kaitan dengan lab sebelumnya: Gunakan database Neon dan skema tabel milik kelompok Anda sendiri yang sudah dibuat di lab 03 — bukan tabel contoh products di modul ini. Jika skema kelompok Anda baru punya satu tabel, tambahkan satu tabel lagi yang berelasi (misalnya kategori, pemilik, atau status) sebelum melanjutkan, karena lab ini mewajibkan minimal dua tabel yang saling terhubung untuk dipraktikkan sebagai nested query.
Tujuan Pembelajaran
  • 01Mahasiswa mampu menghubungkan aplikasi Node.js ke database Neon menggunakan connection string.
  • 02Mahasiswa mampu mendefinisikan GraphQL schema (type & query) untuk minimal dua tabel yang saling berelasi dari skema Neon kelompok masing-masing.
  • 03Mahasiswa mampu menulis resolver yang mengambil data nyata dari Neon, termasuk resolver untuk field relasi antar tabel (nested query).
  • 04Mahasiswa mampu men-deploy GraphQL server ke Render dan mengaksesnya lewat URL publik.
Alat yang Dibutuhkan

Tools Praktikum

Node.js + Apollo Server wajib
Runtime dan library utama untuk membangun GraphQL server.
Paket pg wajib
Driver PostgreSQL untuk Node.js, dipakai menghubungkan resolver ke database Neon.
Akun Neon (dari lab 01) wajib

Akun Render (dari lab 01) wajib

Langkah Praktik

Membangun & Men-deploy GraphQL Server

01

Inisialisasi Proyek & Dependensi

Buat folder proyek baru, lalu instal Apollo Server dan driver PostgreSQL:

# inisialisasi project npm init -y npm install @apollo/server graphql pg dotenv
02

Simpan Connection String Neon

Salin connection string dari dashboard Neon (proyek yang sudah dibuat di lab 03), simpan di file .env:

DATABASE_URL=postgresql://user:password@ep-xxxx.neon.tech/dbname
03

Definisikan Schema GraphQL untuk Dua Tabel

Ganti contoh di bawah ini dengan skema tabel milik kelompok Anda sendiri dari lab 03. Contoh ini memakai dua tabel berelasi: categories dan products (satu kategori punya banyak produk):

const typeDefs = \` type Category { id: ID! name: String! products: [Product!]! } type Product { id: ID! name: String! price: Float! stock: Int! category: Category! } type Query { categories: [Category!]! products: [Product!]! product(id: ID!): Product } \`;
04

Tulis Resolver, Termasuk Resolver Relasi

Selain resolver untuk Query, tambahkan resolver di level type untuk menjembatani relasi antar tabel — inilah yang membuat nested query di GraphQL bekerja:

const resolvers = { Query: { categories: async () => { const result = await pool.query('SELECT * FROM categories'); return result.rows; }, products: async () => { const result = await pool.query('SELECT * FROM products'); return result.rows; }, product: async (_, { id }) => { const result = await pool.query('SELECT * FROM products WHERE id = $1', [id]); return result.rows[0]; } }, Product: { category: async (parent) => { const result = await pool.query('SELECT * FROM categories WHERE id = $1', [parent.category_id]); return result.rows[0]; } }, Category: { products: async (parent) => { const result = await pool.query('SELECT * FROM products WHERE category_id = $1', [parent.id]); return result.rows; } } };
05

Jalankan & Uji Lokal dengan Nested Query

Jalankan server lokal, lalu buka Apollo Sandbox (biasanya di http://localhost:4000). Coba query yang melibatkan kedua tabel sekaligus dalam satu request, misalnya:

query { categories { name products { name price } } }

Kalau hasilnya menampilkan produk bersarang di dalam masing-masing kategori, resolver relasi Anda sudah bekerja dengan benar.

06

Deploy ke Render

Push kode ke GitHub, lalu di dashboard Render: buat "New Web Service", hubungkan ke repository, dan tambahkan environment variable DATABASE_URL (isi dengan connection string Neon yang sama). Setelah deploy selesai, uji query yang sama lewat URL publik Render.

Alternatif Deployment

Memakai Vercel Sebagai Pengganti Render

Kapan cocok dipakai: Vercel adalah platform serverless — cocok untuk GraphQL sederhana seperti ini, tapi strukturnya berbeda dari Render yang server-nya menyala terus-menerus. Kalau Anda lebih familiar dengan Next.js dari Frontend Programming, opsi ini bisa jadi alternatif yang lebih nyaman.
A

Bootstrap dengan Next.js

Vercel mengharapkan struktur serverless function, bukan proses Node.js biasa. Mulai dengan npx create-next-app, lalu pasang integration resmi komunitas Apollo untuk Next.js (bukan package lama yang sudah deprecated):

# jangan pakai @saeris/apollo-server-vercel — sudah deprecated npm install @apollo/server @as-integrations/next graphql pg
B

Buat Handler di pages/api/graphql.js

Schema dan resolver dari langkah 3-4 tetap sama persis — hanya cara membungkusnya yang berbeda, memakai startServerAndCreateNextHandler dari @as-integrations/next.

C

Gunakan Connection String Pooled dari Neon

Ini langkah paling penting: di dashboard Neon, salin connection string yang mengandung akhiran -pooler pada hostname-nya, bukan yang direct. Serverless function bisa memicu banyak koneksi baru secara bersamaan — tanpa pooling, koneksi ke Neon bisa cepat habis (connection limit exceeded).

D

Deploy Lewat Vercel

Hubungkan repository GitHub ke dashboard Vercel (atau jalankan vercel deploy lewat CLI), tambahkan environment variable DATABASE_URL dengan connection string pooled tadi, lalu uji endpoint di https://nama-proyek.vercel.app/api/graphql.

Checklist Kesiapan
  • GraphQL server berhasil terhubung ke database Neon milik kelompok sendiri (bukan data hardcode, bukan tabel contoh modul)
  • Skema mencakup minimal 2 tabel yang saling berelasi, dengan resolver relasi di kedua arah
  • Nested query (mengambil data dari 2 tabel sekaligus dalam 1 request) berhasil dijalankan lewat Apollo Sandbox lokal
  • Server berhasil di-deploy ke Render atau Vercel dan bisa diakses lewat URL publik
  • Nested query yang sama berhasil dijalankan lewat URL deployment (bukan cuma localhost)
  • Jika memakai Vercel: connection string yang dipakai adalah versi pooled (-pooler)
Tugas & Latihan
Latihan Mandiri

Bandingkan langsung: berapa jumlah field yang benar-benar dikembalikan saat Anda meng-query hanya { products { name } } di GraphQL, dibanding kalau resource yang sama diakses lewat endpoint REST biasa (yang biasanya mengembalikan semua field sekaligus). Tuliskan refleksi singkat (3-5 kalimat) tentang kapan perbedaan ini benar-benar berguna dalam aplikasi nyata.

Format pengumpulan:

  • Link Apollo Sandbox yang sudah menunjuk ke endpoint deployment Anda, dengan format:
    https://studio.apollographql.com/sandbox/explorer?endpoint=URL_DEPLOYMENT_ANDA/graphql
  • Screenshot nested query (seperti di langkah 5) yang dijalankan lewat URL deployment — bukan localhost — sebagai bukti kedua tabel benar-benar terhubung dan datanya nyata
  • Refleksi tertulis 3-5 kalimat di atas

Pastikan introspection tidak dimatikan di server Anda, dan CORS mengizinkan domain studio.apollographql.com, supaya link Sandbox bisa dibuka oleh dosen. Kumpulkan sebelum lab 05.
