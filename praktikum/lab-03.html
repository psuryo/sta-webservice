LAB 03

Contract-First Modern: Merancang OpenAPI Spec dari Nol

Mempraktikkan langsung konsep contract-first yang dibahas di kuliah sesi 3 (WSDL) — kali ini dengan OpenAPI Specification, dan berbasis skema database nyata yang Anda buat sendiri di Neon.

Durasi 100 menit
Format Praktikum Mandiri/Berpasangan
Terkait Kuliah Sesi 03 — SOA & SOAP
Kaitan dengan kuliah & lab sebelumnya: Di sesi 03 kuliah, WSDL diperkenalkan sebagai konsep contract-first — kontrak layanan ditulis sebelum kode. Lab ini mempraktikkan ide yang sama dengan OpenAPI, dan sekaligus memanfaatkan akun Neon yang sudah dibuat di lab 01. Bedanya dengan kebiasaan di Backend Programming: kali ini kontrak API dirancang lebih dulu, sebelum endpoint sungguhan ditulis.
Tujuan Pembelajaran
  • 01Mahasiswa mampu membuat skema tabel sederhana di database Neon sebagai dasar rancangan API.
  • 02Mahasiswa mampu menulis dokumen OpenAPI (YAML) dari nol yang merepresentasikan skema data tersebut secara akurat.
  • 03Mahasiswa mampu mendefinisikan path, method, request/response schema, dan status code dalam OpenAPI.
  • 04Mahasiswa mampu memvalidasi dan mem-preview dokumentasi API menggunakan Swagger Editor.
  • 05Mahasiswa mampu menjelaskan mengapa mendesain kontrak sebelum implementasi mempermudah kolaborasi tim.
Alat yang Dibutuhkan

Tools Praktikum

Neon SQL Editor wajib
Console SQL bawaan Neon (dari akun yang sudah dibuat di lab 01) untuk membuat tabel yang jadi dasar rancangan API.
Swagger Editor wajib
editor.swagger.io — bisa langsung dipakai di browser tanpa instalasi, untuk menulis dan mem-preview OpenAPI spec.
VS Code + OpenAPI Extension opsional
Ekstensi seperti "OpenAPI (Swagger) Editor" membantu autocomplete saat menulis YAML secara lokal.
Langkah Praktik

Menulis Spesifikasi dari Nol

01

Definisikan Info Dasar

Mulai dokumen dengan versi OpenAPI, judul, dan versi API:

openapi: 3.0.3 info: title: Buku API version: 1.0.0
02

Tentukan Path & Method

Deskripsikan satu endpoint sederhana, misalnya untuk mengambil daftar buku:

paths: /books: get: summary: Ambil daftar buku responses: '200': description: Berhasil
03

Definisikan Schema Data

Tambahkan struktur data buku di bagian components/schemas agar bisa dipakai berulang di berbagai endpoint:

components: schemas: Book: type: object properties: id: type: integer title: type: string
04

Validasi & Preview

Tempel seluruh dokumen ke Swagger Editor (editor.swagger.io). Panel kanan akan otomatis menampilkan dokumentasi interaktif dan menandai error jika ada kesalahan format.

Checklist Kesiapan
  • Dokumen OpenAPI valid tanpa error di Swagger Editor
  • Minimal 2 endpoint terdefinisi (contoh: GET /books dan POST /books)
  • Schema data (components/schemas) sudah dipakai lewat $ref, bukan ditulis ulang manual
  • Setiap response punya status code dan deskripsi yang jelas
Tugas & Latihan
Latihan Mandiri

Pilih satu resource dari topik proyek kelompok Anda di praktikum (misalnya "produk", "pesanan", atau "pengguna"). Tulis dokumen OpenAPI lengkap untuk resource tersebut dengan minimal 4 endpoint (GET list, GET by id, POST, dan DELETE), lengkap dengan schema request/response. Simpan file .yaml dan kumpulkan sebelum lab 04.
