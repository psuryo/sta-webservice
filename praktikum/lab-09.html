LAB 09

Memecah Aplikasi Menjadi Microservices

Mengambil satu aplikasi monolit kecil, memecahnya menjadi dua service dengan data masing-masing, menghubungkannya lewat HTTP, lalu memasangnya di balik gateway dari lab 08. Kode monolit disediakan, jadi waktu Anda terpakai untuk memecah, bukan menulis ulang.

Durasi maks. 2 jam
Format Praktikum Berkelompok
Prasyarat Lab 08 (gateway), Node.js 18+
Kaitan dengan proyek: Contoh toko sederhana (produk + pesanan) dipakai agar semua kelompok punya titik awal yang sama dan bisa selesai tepat waktu. Pola yang dipelajari (satu service satu data, komunikasi lewat API, gateway di depan) langsung Anda terapkan ke sistem proyek kelompok pada bagian Tugas. Komunikasi di lab ini sinkron (HTTP); versi asinkron dibahas di lab 10.
Tujuan Pembelajaran
  • 01Mahasiswa mampu menentukan batas service dari sebuah aplikasi monolit berdasarkan data dan tanggung jawabnya.
  • 02Mahasiswa mampu memecah monolit menjadi dua service yang berjalan dan memiliki data sendiri-sendiri.
  • 03Mahasiswa mampu menghubungkan dua service lewat panggilan HTTP dengan timeout dan penanganan error.
  • 04Mahasiswa mampu membuktikan bahwa kegagalan satu service tidak mematikan seluruh sistem.
Gambaran Arsitektur

Sebelum dan Sesudah

SEBELUM: satu proses, satu data Klien ──▶ monolith :3000 [ /products /orders ] └─ array products & orders di memori yang sama SESUDAH: dua proses, masing-masing punya data Klien ──▶ gateway :8080 ├─ /product-service/* ──▶ product-service :3000 [data: products] └─ /order-service/* ──▶ order-service :3001 [data: orders] │ └─ HTTP ──▶ product-service (cek & kurangi stok)

Aturan utama: order-service tidak boleh membaca data produk secara langsung. Jika butuh stok atau harga, ia bertanya lewat API product-service.

Langkah Praktik

Dari Monolit ke Dua Service

01

Jalankan Monolit

Buat folder toko/monolith, lalu siapkan project (cek node -v minimal 18):

mkdir -p toko/monolith && cd toko/monolith npm init -y npm install express

Simpan sebagai monolith.js, jalankan node monolith.js:

const express = require('express'); const app = express(); app.use(express.json()); const products = [ { id: 1, name: 'Keyboard Mekanik', price: 450000, stock: 10 }, { id: 2, name: 'Mouse Wireless', price: 175000, stock: 25 }, { id: 3, name: 'Monitor 24 inci', price: 1850000, stock: 5 }, ]; const orders = []; app.get('/products', (req, res) => res.json(products)); app.get('/products/:id', (req, res) => { const p = products.find(x => x.id === Number(req.params.id)); p ? res.json(p) : res.status(404).json({ error: 'Produk tidak ditemukan' }); }); app.post('/orders', (req, res) => { const { productId, qty } = req.body || {}; const p = products.find(x => x.id === productId); if (!p) return res.status(404).json({ error: 'Produk tidak ditemukan' }); if (!Number.isInteger(qty) || qty < 1) return res.status(400).json({ error: 'qty tidak valid' }); if (p.stock < qty) return res.status(409).json({ error: 'Stok tidak cukup' }); p.stock -= qty; // <-- order mengubah data produk secara langsung const order = { id: orders.length + 1, productId, productName: p.name, qty, total: p.price * qty, createdAt: new Date().toISOString() }; orders.push(order); res.status(201).json(order); }); app.get('/orders', (req, res) => res.json(orders)); app.listen(3000, () => console.log('Monolith di :3000'));

Uji di Postman: GET /products, lalu POST /orders dengan body {"productId":1,"qty":2}, lalu GET /products/1 (stok turun jadi 8). Setelah paham, hentikan monolit (Ctrl+C).

03

Bangun product-service (port 3000)

cd toko && mkdir product-service && cd product-service npm init -y && npm install express

Simpan sebagai product-service.js. Bagian produk disalin dari monolit, ditambah endpoint reserve:

const express = require('express'); const app = express(); app.use(express.json()); const products = [ { id: 1, name: 'Keyboard Mekanik', price: 450000, stock: 10 }, { id: 2, name: 'Mouse Wireless', price: 175000, stock: 25 }, { id: 3, name: 'Monitor 24 inci', price: 1850000, stock: 5 }, ]; app.get('/products', (req, res) => res.json(products)); app.get('/products/:id', (req, res) => { const p = products.find(x => x.id === Number(req.params.id)); p ? res.json(p) : res.status(404).json({ error: 'Produk tidak ditemukan' }); }); // endpoint baru: dipanggil service lain untuk mengurangi stok app.post('/products/:id/reserve', (req, res) => { const p = products.find(x => x.id === Number(req.params.id)); const qty = (req.body || {}).qty; if (!p) return res.status(404).json({ error: 'Produk tidak ditemukan' }); if (!Number.isInteger(qty) || qty < 1) return res.status(400).json({ error: 'qty tidak valid' }); if (p.stock < qty) return res.status(409).json({ error: 'Stok tidak cukup' }); p.stock -= qty; res.json(p); }); app.listen(process.env.PORT || 3000, () => console.log('product-service di :3000'));

Jalankan dengan node product-service.js dan uji GET /products serta POST /products/1/reserve (body {"qty":1}) langsung di port 3000.

04

Bangun order-service (port 3001)

cd ../ && mkdir order-service && cd order-service npm init -y && npm install express

Simpan sebagai order-service.js. Perhatikan: tidak ada array products di sini, hanya panggilan HTTP dengan timeout 2 detik.

const express = require('express'); const app = express(); app.use(express.json()); const PRODUCT_URL = process.env.PRODUCT_SERVICE_URL || 'http://localhost:3000'; const orders = []; app.post('/orders', async (req, res) => { const { productId, qty } = req.body || {}; if (!Number.isInteger(productId) || !Number.isInteger(qty) || qty < 1) return res.status(400).json({ error: 'productId dan qty harus bilangan bulat > 0' }); let resp; try { resp = await fetch(`${PRODUCT_URL}/products/${productId}/reserve`, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ qty }), signal: AbortSignal.timeout(2000), }); } catch (err) { return res.status(503).json({ error: 'product-service tidak tersedia, coba lagi nanti' }); } const data = await resp.json(); if (!resp.ok) return res.status(resp.status).json(data); // 404 / 409 diteruskan apa adanya const order = { id: orders.length + 1, productId, productName: data.name, qty, total: data.price * qty, createdAt: new Date().toISOString() }; orders.push(order); res.status(201).json(order); }); app.get('/orders', (req, res) => res.json(orders)); app.listen(process.env.PORT || 3001, () => console.log('order-service di :3001'));

Jalankan di terminal ketiga: node order-service.js. Uji langsung di port 3001: POST /orders dengan {"productId":1,"qty":2}, lalu cek stok di GET localhost:3000/products/1. Hasilnya harus sama dengan monolit.

05

Pasang di Gateway & Uji End-to-End

Salin folder gateway dari lab 08 ke toko/gateway. Di gateway.js, ganti prefix /service-a menjadi /product-service dan /service-b menjadi /order-service (di pathFilter dan pathRewrite). Target bawaan (:3000 dan :3001) sudah sesuai. Jika Anda mengerjakan tantangan API key lab 08, sesuaikan juga prefix-nya dan sertakan header X-API-Key saat menguji.

Jalankan gateway (node gateway.js), lalu simpan skrip berikut sebagai smoke-test.js di folder toko:

const BASE = process.env.BASE_URL || 'http://localhost:8080'; const json = { 'Content-Type': 'application/json' }; (async () => { const list = await fetch(`${BASE}/product-service/products`).then(r => r.json()); console.log('jumlah produk:', list.length); const o = await fetch(`${BASE}/order-service/orders`, { method: 'POST', headers: json, body: JSON.stringify({ productId: 1, qty: 2 }) }); console.log('buat order:', o.status, await o.json()); const p = await fetch(`${BASE}/product-service/products/1`).then(r => r.json()); console.log('stok produk 1 sekarang:', p.stock); })();

Jalankan node smoke-test.js. Harapan: jumlah produk 3, status order 201, stok berkurang 2. Jika gateway lab 08 belum jadi, lewati langkah ini, arahkan BASE_URL secara manual ke masing-masing port, dan selesaikan gateway sebagai pekerjaan rumah.

06

Uji Kegagalan Service

Inilah alasan utama memecah monolit: satu bagian mati, sisanya tetap hidup. Lakukan berurutan lewat Postman atau gateway:

  • Matikan product-service (Ctrl+C di terminalnya). Kirim POST /order-service/orders: harus kembali 503 dengan pesan jelas, bukan menggantung atau crash.
  • Kirim GET /order-service/orders: harus tetap 200, karena order-service masih sehat. Pada monolit, hal ini mustahil karena semua mati bersama.
  • Nyalakan kembali product-service dan ulangi POST: harus 201. Catat bahwa stok kembali ke data awal, karena data hanya di memori.
  • Uji timeout (opsional): di reserve, tambahkan sementara await new Promise(r => setTimeout(r, 5000)); (jadikan handler async) dan amati order-service membalas 503 setelah sekitar 2 detik. Hapus kembali baris itu.

Ambil screenshot ketiga hasil pertama sebagai bukti.

07

Diagram, Commit & Bukti

Buat diagram sederhana (draw.io, Mermaid, atau tangan lalu difoto) arsitektur toko setelah dipecah. Commit seluruh folder (gateway, product-service, order-service, smoke-test.js, tanpa node_modules) ke satu repository GitHub. Tambahkan .gitignore berisi node_modules dan .env.

Kesalahan Umum
Masalah yang Sering Muncul
EADDRINUSE: address already in use :::3000

Monolit atau proses lama masih berjalan. Hentikan dengan Ctrl+C di terminalnya (pastikan monolit sudah dimatikan sebelum menyalakan product-service).

503 padahal product-service menyala

Periksa port: PRODUCT_URL di order-service harus sama dengan port product-service (3000). Di Windows, coba 127.0.0.1 jika localhost gagal.

fetch is not defined

Versi Node.js di bawah 18. Cek dengan node -v dan perbarui.

POST lewat gateway menggantung

Pastikan tidak ada express.json() sebelum middleware proxy di gateway (lihat kesalahan umum lab 08).

404 dari service lewat gateway

Prefix di pathFilter dan pathRewrite tidak sama, atau URL yang Anda panggil masih memakai prefix lama (/service-a).

Checklist Kesiapan
  • Monolit berjalan dan Anda tahu bagian mana yang saling mengikat
  • product-service dan order-service berjalan di port berbeda, masing-masing dengan datanya sendiri
  • order-service tidak punya data produk; ia memanggil reserve lewat HTTP dengan timeout
  • smoke-test.js lewat gateway berhasil: order 201, stok berkurang
  • Saat product-service mati: POST /orders menjadi 503, GET /orders tetap 200
  • Tidak ada secret atau node_modules di repository
