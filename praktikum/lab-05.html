LAB 05

Query & Mutation Lanjutan GraphQL

Melengkapi server GraphQL dari lab 04 (yang baru bisa membaca data) dengan kemampuan menulis data — create, update, delete — plus query dengan filter.

Durasi 100 menit
Format Praktikum Berkelompok
Terkait Lab 04 — GraphQL Sederhana
Kaitan dengan lab sebelumnya: Lanjutkan langsung dari project lab 04 — schema, resolver, dan koneksi Neon yang sudah ada tidak perlu dibuat ulang. Lab ini hanya menambahkan Mutation dan filter Query ke schema yang sudah berjalan.
Tujuan Pembelajaran
  • 01Mahasiswa mampu menambahkan Mutation (create, update, delete) ke schema GraphQL yang sudah ada.
  • 02Mahasiswa mampu menggunakan Input Type untuk merapikan parameter mutation yang kompleks.
  • 03Mahasiswa mampu menulis resolver mutation yang benar-benar mengubah data di Neon (INSERT/UPDATE/DELETE), bukan simulasi.
  • 04Mahasiswa mampu menambahkan argument filter pada Query yang sudah ada (mis. produk berdasarkan kategori).
  • 05Mahasiswa mampu memverifikasi keberhasilan mutation dengan pola "mutation lalu query ulang".
Langkah Praktik

Menambahkan Mutation & Filter

01

Tambahkan Input Type & Mutation ke Schema

Buka file typeDefs dari lab 04, tambahkan bagian berikut tanpa menghapus yang sudah ada:

const typeDefs = \` # ...type Category, type Product, type Query dari lab 04 tetap ada... input CreateProductInput { title: String! price: Float! categoryId: ID! } input UpdateProductInput { title: String price: Float } type Mutation { createProduct(input: CreateProductInput!): Product! updateProduct(id: ID!, input: UpdateProductInput!): Product! deleteProduct(id: ID!): Boolean! } \`;
02

Tulis Resolver Mutation

Tambahkan blok Mutation di objek resolvers yang sudah ada, sejajar dengan Query:

const resolvers = { // ...Query, Product, Category dari lab 04 tetap ada... Mutation: { createProduct: async (_, { input }) => { const result = await pool.query( 'INSERT INTO products (title, price, category_id) VALUES ($1, $2, $3) RETURNING *', [input.title, input.price, input.categoryId] ); return result.rows[0]; }, updateProduct: async (_, { id, input }) => { const result = await pool.query( 'UPDATE products SET title = COALESCE($1, title), price = COALESCE($2, price) WHERE id = $3 RETURNING *', [input.title, input.price, id] ); return result.rows[0]; }, deleteProduct: async (_, { id }) => { await pool.query('DELETE FROM products WHERE id = $1', [id]); return true; } } };

Catatan: COALESCE dipakai supaya field yang tidak dikirim di UpdateProductInput (bernilai null/undefined) tidak menimpa data lama dengan kosong.

03

Tambahkan Filter ke Query yang Sudah Ada

Ubah field products di type Query supaya menerima parameter opsional, lalu sesuaikan resolver-nya:

type Query { products(categoryId: ID): [Product!]! # ...field lain tetap sama... } // di resolver: products: async (_, { categoryId }) => { if (categoryId) { const result = await pool.query( 'SELECT * FROM products WHERE category_id = $1', [categoryId] ); return result.rows; } const result = await pool.query('SELECT * FROM products'); return result.rows; }
04

Uji Mutation dengan Pola "Mutation lalu Query"

Jalankan lokal, buka Apollo Sandbox, lalu jalankan mutation berikut:

mutation { createProduct(input: { title: "Produk Uji", price: 10000, categoryId: "1" }) { id title } }

Catat id yang dikembalikan, lalu langsung jalankan query products — pastikan produk baru itu benar-benar muncul di hasilnya. Ini pola verifikasi yang sama dipakai untuk menilai tugas ini nanti.

05

Redeploy

Push perubahan ke GitHub — Render/Vercel akan otomatis men-deploy ulang. Uji sekali lagi mutation dan query yang sama lewat URL publik (bukan cuma localhost).

Kesalahan Umum
Error yang Sering Muncul di Apollo Sandbox
Field harus punya selection set

Kalau sebuah field mengembalikan object type (bukan angka/teks polos), wajib ada minimal 1 field di dalam { }-nya. Contoh: createProduct(...) { } kosong akan error — isi minimal { id }.

Cannot query field "x" on type "Y"

Field yang diminta tidak ada di type tersebut menurut schema — biasanya field-nya sebenarnya ada, tapi di type lain (mis. title ada di Product, bukan di Category). Cek panel Fields di kiri Sandbox untuk memastikan field itu benar-benar milik type yang sedang di-query.

Unknown argument "x" on field "Y"

Argumen yang dipakai di query tidak terdaftar di schema untuk field tersebut. Kalau memang butuh, argumen itu harus ditambahkan dulu ke schema (dan resolver-nya), bukan langsung dipakai di query.

Checklist Kesiapan
  • Mutation createProduct, updateProduct, dan deleteProduct berhasil dijalankan dan benar-benar mengubah data di Neon
  • Query products(categoryId: ID) berhasil memfilter hasil sesuai kategori
  • Verifikasi mutation-lalu-query sudah dicoba: data baru/terupdate/terhapus benar-benar terlihat di query berikutnya
  • Semua perubahan sudah di-redeploy dan diuji ulang lewat URL publik
Tugas & Latihan
Latihan Mandiri

Lakukan urutan berikut lewat Apollo Sandbox yang menunjuk ke endpoint deployment Anda: (1) jalankan createProduct, (2) jalankan query products untuk membuktikan produk baru muncul, (3) jalankan updateProduct pada produk tersebut, (4) query ulang untuk membuktikan perubahan tersimpan, (5) jalankan deleteProduct, (6) query ulang untuk membuktikan produk sudah hilang.

Format pengumpulan: link Apollo Sandbox (?endpoint=URL_DEPLOYMENT_ANDA/graphql) beserta screenshot dari keenam langkah di atas, dan refleksi singkat (2-3 kalimat) apa yang lebih rumit ditulis di GraphQL mutation dibanding endpoint REST POST/PUT/DELETE biasa. Kumpulkan sebelum lab 06.
