LAB 12

Automated Testing & Monitoring API

Membuat pengujian otomatis untuk toko, menambahkan health check, metrik, dan log terstruktur dengan ID permintaan yang bisa dilacak lintas service, lalu memantau sistem dengan skrip monitor sederhana. Seluruh test dijalankan otomatis di GitHub Actions pada setiap push.

Durasi maks. 2 jam
Format Praktikum Berkelompok
Prasyarat Lab 09 (toko + gateway), Node.js 18+, akun GitHub
Kaitan dengan lab sebelumnya dan proyek: Di lab 09 Anda mengecek hasil dengan Postman secara manual dan di lab 11 mendokumentasikan kode status tiap endpoint. Kini janji itu diperiksa mesin setiap kali dijalankan. Lab 10 dan 11 tidak wajib; bila sudah ada, gunakan hasilnya. Test dan monitor ini langsung memperkuat demo proyek akhir: sistem yang bisa membuktikan dirinya sehat lebih meyakinkan daripada sistem yang hanya "berjalan di laptop". GitHub Actions menjalankan test di mesin bersih milik GitHub, sehingga hasilnya tidak bergantung pada laptop Anda.
Tujuan Pembelajaran
  • 01Mahasiswa mampu menulis dan menjalankan pengujian API otomatis yang memeriksa status, bentuk respons, dan efek samping.
  • 02Mahasiswa mampu menunjukkan bagaimana test menangkap regresi saat kode diubah.
  • 03Mahasiswa mampu menambahkan health check, metrik dasar, dan log terstruktur pada service.
  • 04Mahasiswa mampu melacak satu permintaan lintas gateway dan dua service lewat ID permintaan, serta memantau ketersediaan dengan skrip monitor.
  • 05Mahasiswa mampu membuat workflow GitHub Actions yang menjalankan seluruh service dan test pada setiap push, serta membaca hasil run yang hijau maupun merah.
Gambaran Arsitektur

Yang Ditambahkan

tests/api.test.js ──HTTP──▶ gateway :8080 ──▶ product-service :3000 │ (X-Request-Id dibuat) ▲ └──▶ order-service :3001 ───┘ (ID diteruskan) monitor.js ──GET /health tiap beberapa detik──▶ gateway, product, order UP/DOWN + latency, ALERT saat berubah Tiap service: /health, /metrics, dan log JSON per permintaan (memuat id yang sama) .github/workflows/ci.yml ──push──▶ GitHub Actions: nyalakan 3 service, lalu jalankan npm test
Langkah Praktik

Dari Uji Manual ke Uji Otomatis

01

Siapkan Folder Test

Jalankan product-service, order-service, dan gateway seperti di lab 09 (RabbitMQ tidak perlu). Lalu di folder toko:

node -v # minimal 18 mkdir tests npm init -y # membuat toko/package.json

Ubah bagian "scripts" pada toko/package.json menjadi "test": "node --test tests/api.test.js". Kita memakai test runner bawaan Node.js, jadi tidak ada paket tambahan.

02

Tulis Test Otomatis

Simpan sebagai tests/api.test.js. Test berjalan terhadap gateway seperti klien sungguhan (black-box) dan memakai perbandingan relatif agar tidak rusak oleh stok yang berubah.

const { test } = require('node:test'); const assert = require('node:assert/strict'); const BASE = process.env.BASE_URL || 'http://localhost:8080'; const json = { 'Content-Type': 'application/json' }; const get = (p) => fetch(BASE + p); const post = (p, body) => fetch(BASE + p, { method: 'POST', headers: json, body: JSON.stringify(body) }); let createdOrder; test('GET /products mengembalikan daftar produk yang bentuknya benar', async () => { const res = await get('/product-service/products'); assert.equal(res.status, 200); const list = await res.json(); assert.ok(Array.isArray(list) && list.length > 0); for (const p of list) { assert.equal(typeof p.id, 'number'); assert.equal(typeof p.name, 'string'); assert.equal(typeof p.price, 'number'); assert.equal(typeof p.stock, 'number'); } }); test('GET /products/:id mengembalikan satu produk', async () => { const res = await get('/product-service/products/1'); assert.equal(res.status, 200); assert.equal((await res.json()).id, 1); }); test('GET /products/:id untuk id tak dikenal mengembalikan 404', async () => { const res = await get('/product-service/products/9999'); assert.equal(res.status, 404); assert.ok((await res.json()).error); }); test('POST /orders berhasil (201) dan mengurangi stok produk', async () => { const before = await (await get('/product-service/products/2')).json(); const res = await post('/order-service/orders', { productId: 2, qty: 1 }); assert.equal(res.status, 201); createdOrder = await res.json(); assert.equal(createdOrder.productId, 2); assert.equal(createdOrder.qty, 1); assert.equal(createdOrder.total, before.price); const after = await (await get('/product-service/products/2')).json(); assert.equal(after.stock, before.stock - 1); }); test('POST /orders dengan qty melebihi stok mengembalikan 409', async () => { const res = await post('/order-service/orders', { productId: 2, qty: 100000 }); assert.equal(res.status, 409); }); test('POST /orders dengan input tidak valid mengembalikan 400', async () => { assert.equal((await post('/order-service/orders', { productId: 2, qty: 0 })).status, 400); assert.equal((await post('/order-service/orders', { productId: 2, qty: 'abc' })).status, 400); }); test('POST /orders untuk produk tak dikenal mengembalikan 404', async () => { const res = await post('/order-service/orders', { productId: 9999, qty: 1 }); assert.equal(res.status, 404); }); test('GET /orders memuat pesanan yang baru dibuat', async () => { const list = await (await get('/order-service/orders')).json(); assert.ok(list.some(o => o.id === createdOrder.id)); });

Jalankan npm test. Semua test harus lulus (tanda centang). Jalankan dua kali: karena perbandingannya relatif, hasilnya tetap lulus.

03

Biarkan Test Menangkap Regresi

Pada product-service.js, di endpoint reserve, ubah sementara status untuk "Stok tidak cukup" dari 409 menjadi 400. Restart service dan jalankan npm test. Test 409 harus gagal dengan pesan yang menyebut nilai diharapkan dan nilai aktual. Baca pesannya: inilah yang membuat perubahan yang merusak ketahuan sebelum sampai ke pengguna. Kembalikan ke 409, restart, dan pastikan test kembali lulus.

04

Tambahkan Health, Metrik, dan Log Terstruktur

Buat file observability.js dengan isi yang sama di folder product-service dan order-service (menyalin file adalah kompromi agar tiap service tetap mandiri saat di-deploy):

const crypto = require('crypto'); module.exports = function observability(app, service) { const stats = { startedAt: new Date().toISOString(), requests: 0, errors5xx: 0, totalMs: 0 }; app.use((req, res, next) => { if (req.path === '/health') return next(); // jangan ramaikan log dengan polling const id = req.headers['x-request-id'] || crypto.randomUUID(); req.id = id; res.setHeader('X-Request-Id', id); const t0 = process.hrtime.bigint(); res.on('finish', () => { const ms = Number(process.hrtime.bigint() - t0) / 1e6; stats.requests++; stats.totalMs += ms; if (res.statusCode >= 500) stats.errors5xx++; console.log(JSON.stringify({ time: new Date().toISOString(), service, id, method: req.method, path: req.originalUrl, status: res.statusCode, ms: Math.round(ms) })); }); next(); }); app.get('/health', (req, res) => res.json({ status: 'ok', service, uptimeSec: Math.round(process.uptime()) })); app.get('/metrics', (req, res) => res.json({ service, startedAt: stats.startedAt, requests: stats.requests, errors5xx: stats.errors5xx, avgMs: stats.requests ? Math.round(stats.totalMs / stats.requests) : 0 })); };

Di product-service.js dan order-service.js, tambahkan tepat di bawah app.use(express.json()); (sebelum rute lain):

require('./observability')(app, 'product-service'); // di order-service: 'order-service'

Restart kedua service, lalu buka http://localhost:3000/health dan http://localhost:3001/metrics. Jalankan npm test lagi dan amati log JSON bermunculan di terminal tiap service.

05

Lacak Satu Permintaan Lintas Service

Pada gateway.js, tambahkan sebelum middleware proxy:

const crypto = require('crypto'); app.use((req, res, next) => { req.headers['x-request-id'] = req.headers['x-request-id'] || crypto.randomUUID(); res.setHeader('X-Request-Id', req.headers['x-request-id']); next(); }); app.get('/health', (req, res) => res.json({ status: 'ok', service: 'gateway' }));

Pada order-service.js, di panggilan fetch ke product-service, tambahkan header ID agar diteruskan: headers: { 'Content-Type': 'application/json', 'X-Request-Id': req.id }. Restart gateway dan order-service.

Kirim satu POST /order-service/orders lewat Postman dan salin nilai header X-Request-Id pada respons. Cari nilai itu di log order-service dan product-service: kedua baris memuat id yang sama. Itulah cara melacak satu transaksi yang melewati beberapa service.

06

Pantau dengan Skrip Monitor

Simpan sebagai toko/monitor.js dan jalankan node monitor.js:

const TARGETS = [ { name: 'gateway', url: process.env.GATEWAY_URL || 'http://localhost:8080' }, { name: 'product-service', url: process.env.PRODUCT_URL || 'http://localhost:3000' }, { name: 'order-service', url: process.env.ORDER_URL || 'http://localhost:3001' }, ]; const INTERVAL = Number(process.env.INTERVAL_MS) || 5000; const last = {}; async function check(t) { const t0 = Date.now(); try { const res = await fetch(t.url + '/health', { signal: AbortSignal.timeout(2000) }); return { up: res.ok, ms: Date.now() - t0 }; } catch { return { up: false, ms: Date.now() - t0 }; } } async function tick() { const results = await Promise.all(TARGETS.map(check)); console.log(new Date().toISOString().slice(11, 19), TARGETS.map((t, i) => `${t.name}=${results[i].up ? 'UP' : 'DOWN'}(${results[i].ms}ms)`).join(' ')); TARGETS.forEach((t, i) => { const up = results[i].up; if (last[t.name] === true && !up) console.log(`ALERT: ${t.name} DOWN`); if (last[t.name] === false && up) console.log(`RECOVERED: ${t.name}`); last[t.name] = up; }); } tick(); setInterval(tick, INTERVAL);

Biarkan monitor berjalan, lalu matikan product-service: dalam beberapa detik muncul ALERT. Kirim beberapa order saat itu (hasilnya 503), nyalakan lagi service tersebut sampai muncul RECOVERED, lalu buka http://localhost:3001/metrics: errors5xx mencerminkan kegagalan tadi.

07

Tambah Test Sendiri

Tambahkan ke tests/api.test.js satu test untuk GET /product-service/health (status 200 dan status === 'ok') dan satu test yang memeriksa bahwa respons POST /order-service/orders memuat header X-Request-Id. Pastikan npm test lulus di laptop Anda sebelum lanjut.

08

Jalankan Test Otomatis di GitHub Actions

Langkah ini wajib. Asumsinya isi folder toko (gateway, product-service, order-service, tests, package.json) berada di akar repository, dan package-lock.json tiap service ikut di-commit (node_modules tidak). Buat file .github/workflows/ci.yml (nama folder diawali titik):

name: CI on: [push, pull_request] jobs: test: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-node@v4 with: node-version: 22 - name: Install dependencies run: | npm ci --prefix product-service npm ci --prefix order-service npm ci --prefix gateway - name: Start services run: | node product-service/product-service.js > product.log 2>&1 & node order-service/order-service.js > order.log 2>&1 & node gateway/gateway.js > gateway.log 2>&1 & - name: Wait until services are ready run: | for url in http://localhost:3000/health http://localhost:3001/health http://localhost:8080/health; do ok=0 for i in $(seq 1 30); do if curl -sf "$url" > /dev/null; then ok=1; break; fi sleep 1 done [ "$ok" = 1 ] || { echo "Tidak siap: $url"; exit 1; } done - name: Run tests run: npm test - name: Show service logs if: always() run: | for f in product order gateway; do echo "=== $f ==="; cat $f.log; done

Commit dan push ke main, lalu buka tab Actions di GitHub. Run harus berstatus hijau. Buka langkah Show service logs: log JSON kedua service dari lab ini muncul di sana, termasuk id permintaan. Jika order-service Anda sudah memuat kode RabbitMQ dari lab 10, peringatan koneksi RabbitMQ di log CI itu normal.

Bukti run merah. Buat branch dengan git checkout -b uji-gagal, ubah status 409 menjadi 400 seperti di langkah 03, lalu git push -u origin uji-gagal. Run pada branch itu harus merah; buka langkah Run tests dan temukan test yang gagal. Setelah screenshot, kembali ke main (git checkout main); branch itu tidak perlu digabung.

Badge. Tambahkan di baris pertama README.md: ![CI](https://github.com/USERNAME/REPO/actions/workflows/ci.yml/badge.svg), dengan USERNAME dan REPO diganti milik Anda. Commit semua perubahan ke main.

Kesalahan Umum
Masalah yang Sering Muncul
TypeError: fetch failed / ECONNREFUSED

Salah satu service atau gateway belum menyala. Test dijalankan terhadap sistem yang hidup, jadi nyalakan semuanya lebih dulu.

Test gagal dengan 429 Too Many Requests

Batas laju (rate limit) dari lab 08 terlampaui. Tunggu beberapa detik lalu ulangi, atau arahkan sementara BASE_URL ke service langsung.

Test gagal dengan 401 / 403

API key dari tantangan lab 08 aktif. Tambahkan header X-API-Key pada helper get dan post.

Test 409 atau stok gagal setelah banyak percobaan

Data hanya di memori. Restart product-service dan order-service untuk mengembalikan data awal.

ID di log order-service dan product-service berbeda

Header X-Request-Id belum diteruskan pada fetch di order-service, atau middleware ID di gateway diletakkan setelah proxy.

Cannot GET /health lewat gateway

Rute /health gateway harus sebelum proxy. Untuk service, gunakan /product-service/health atau langsung ke port service.

node: bad option: --test

Versi Node.js terlalu lama. Cek node -v dan perbarui ke 18 atau lebih baru.

Workflow tidak muncul di tab Actions

File harus bernama .github/workflows/ci.yml di akar repository dan sudah di-push. Periksa ejaan folder (titik di depan .github, workflows jamak) dan indentasi YAML (spasi, bukan tab).

npm ci can only install with an existing package-lock.json

package-lock.json belum ter-commit (cek .gitignore). Jalankan npm install di folder service tersebut, lalu commit file lock-nya.

Lulus di laptop, merah di CI (Cannot find module './observability')

File belum ter-commit (cek git status) atau huruf besar/kecil nama file berbeda; Linux di GitHub membedakan huruf, Windows tidak.

Tidak siap: http://localhost:3000/health (langkah Wait)

Service crash saat dinyalakan. Buka langkah Show service logs pada run yang sama; penyebab umum: modul belum ter-commit atau port berbeda dari yang diasumsikan workflow.

No such file or directory: product-service/product-service.js

Nama file atau struktur folder Anda berbeda dari asumsi, atau seluruh folder toko berada di dalam sub-folder repository. Sesuaikan path pada workflow atau pindahkan isinya ke akar.

Tugas & Latihan
Tugas Kelompok

Kumpulkan: (1) tautan repository, (2) screenshot npm test yang lulus, (3) screenshot test gagal (langkah 03) beserta hasil setelah diperbaiki, (4) potongan log kedua service yang memuat id yang sama, (5) screenshot monitor yang menampilkan ALERT dan RECOVERED, (6) tautan ke halaman Actions yang menampilkan run hijau pada main, screenshot run merah pada branch uji-gagal, dan README yang memuat badge CI.

Penerapan ke proyek kelompok: setiap anggota menambahkan endpoint /health dan minimal tiga test otomatis untuk service tanggung jawabnya (satu jalur sukses, satu jalur error, satu efek samping). Sesuaikan TARGETS pada monitor.js dengan komponen sistem kelompok, dan perbarui ci.yml agar menjalankan semua service sistem kelompok.
