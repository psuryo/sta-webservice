LAB 11

Dokumentasi API Otomatis (OpenAPI/Swagger)

Membuat dokumentasi interaktif untuk setiap service toko langsung dari kode, lalu menggabungkannya menjadi satu halaman dokumentasi di gateway. Di lab 03 spesifikasi ditulis lebih dulu; kali ini spesifikasi dihasilkan dari kode yang sudah berjalan.

Durasi maks. 2 jam
Format Praktikum Berkelompok
Prasyarat Lab 09 (toko + gateway), Lab 03 (dasar OpenAPI)
Kaitan dengan lab sebelumnya dan proyek: Lab 03 memakai pendekatan contract-first (kontrak dulu, kode kemudian). Di sini Anda memakai pendekatan code-first (kode dulu, dokumentasi dihasilkan dari anotasi) dan merasakan kelebihan serta risikonya. Hasilnya langsung dipakai di proyek kelompok: dokumentasi API adalah bahan utama bagi anggota lain, dan bagi dokumen desain UAS kuliah. Lab 10 tidak wajib untuk lab ini; jika RabbitMQ tidak dijalankan, order-service hanya menampilkan peringatan di log.
Tujuan Pembelajaran
  • 01Mahasiswa mampu menghasilkan spesifikasi OpenAPI dan Swagger UI dari anotasi pada kode service.
  • 02Mahasiswa mampu menggabungkan dokumentasi beberapa service menjadi satu halaman melalui gateway.
  • 03Mahasiswa mampu menguji endpoint langsung dari dokumentasi dan memverifikasi bahwa respons sesuai yang didokumentasikan.
  • 04Mahasiswa mampu mengenali dokumentasi yang tidak sinkron dengan kode (drift) dan memperbaikinya.
Gambaran Arsitektur

Dokumentasi Ikut Service

Browser ──▶ gateway :8080/docs (Swagger UI gabungan) │ GET /openapi.json (gabungan, dibuat saat diminta) ├──▶ product-service :3000/openapi.json (+ :3000/docs) └──▶ order-service :3001/openapi.json (+ :3001/docs) Tiap service mendeskripsikan dirinya sendiri; gateway hanya menggabungkan dan menambahkan prefix /product-service dan /order-service pada path.

Dokumentasi dimiliki oleh service yang bersangkutan sehingga berubah bersama kodenya. Gateway tidak menyimpan salinan; ia mengambilnya saat diminta.

Langkah Praktik

Dari Kode ke Dokumentasi

01

Dokumentasikan product-service

cd toko/product-service npm install swagger-jsdoc swagger-ui-express

Pada product-service.js, tambahkan di bawah app.use(express.json());. Komentar yang diawali @openapi adalah YAML; gunakan spasi, bukan tab.

const swaggerJsdoc = require('swagger-jsdoc'); const swaggerUi = require('swagger-ui-express'); const spec = swaggerJsdoc({ definition: { openapi: '3.0.3', info: { title: 'Product Service', version: '1.0.0', description: 'Data produk dan stok' }, servers: [{ url: 'http://localhost:3000' }], }, apis: [__filename], // baca anotasi dari file ini }); app.get('/openapi.json', (req, res) => res.json(spec)); app.use('/docs', swaggerUi.serve, swaggerUi.setup(spec)); /** * @openapi * components: * schemas: * Product: * type: object * properties: * id: { type: integer, example: 1 } * name: { type: string, example: Keyboard Mekanik } * price: { type: integer, example: 450000 } * stock: { type: integer, example: 10 } * ReserveRequest: * type: object * required: [qty] * properties: * qty: { type: integer, minimum: 1, example: 2 } * Error: * type: object * properties: * error: { type: string, example: Produk tidak ditemukan } * /products: * get: * tags: [Products] * summary: Daftar semua produk * responses: * 200: * description: Berhasil * content: * application/json: * schema: * type: array * items: { $ref: '#/components/schemas/Product' } * /products/{id}: * get: * tags: [Products] * summary: Detail satu produk * parameters: * - in: path * name: id * required: true * schema: { type: integer } * responses: * 200: * description: Berhasil * content: * application/json: * schema: { $ref: '#/components/schemas/Product' } * 404: { description: Produk tidak ditemukan, content: { application/json: { schema: { $ref: '#/components/schemas/Error' } } } } * /products/{id}/reserve: * post: * tags: [Products] * summary: Kurangi stok produk (dipanggil service lain) * parameters: * - in: path * name: id * required: true * schema: { type: integer } * requestBody: * required: true * content: * application/json: * schema: { $ref: '#/components/schemas/ReserveRequest' } * responses: * 200: * description: Stok berhasil dikurangi * content: * application/json: * schema: { $ref: '#/components/schemas/Product' } * 400: { description: qty tidak valid, content: { application/json: { schema: { $ref: '#/components/schemas/Error' } } } } * 404: { description: Produk tidak ditemukan, content: { application/json: { schema: { $ref: '#/components/schemas/Error' } } } } * 409: { description: Stok tidak cukup, content: { application/json: { schema: { $ref: '#/components/schemas/Error' } } } } */

Restart service, lalu buka http://localhost:3000/docs. Tiga endpoint harus tampil di grup Products. Cek juga http://localhost:3000/openapi.json.

02

Dokumentasikan order-service

cd ../order-service npm install swagger-jsdoc swagger-ui-express

Pada order-service.js, tambahkan di bawah app.use(express.json()); (pola sama dengan langkah 01, server :3001):

const swaggerJsdoc = require('swagger-jsdoc'); const swaggerUi = require('swagger-ui-express'); const spec = swaggerJsdoc({ definition: { openapi: '3.0.3', info: { title: 'Order Service', version: '1.0.0', description: 'Pembuatan dan daftar pesanan' }, servers: [{ url: 'http://localhost:3001' }], }, apis: [__filename], }); app.get('/openapi.json', (req, res) => res.json(spec)); app.use('/docs', swaggerUi.serve, swaggerUi.setup(spec)); /** * @openapi * components: * schemas: * OrderRequest: * type: object * required: [productId, qty] * properties: * productId: { type: integer, example: 1 } * qty: { type: integer, minimum: 1, example: 2 } * Order: * type: object * properties: * id: { type: integer, example: 1 } * productId: { type: integer, example: 1 } * productName: { type: string, example: Keyboard Mekanik } * qty: { type: integer, example: 2 } * total: { type: integer, example: 900000 } * createdAt: { type: string, format: date-time } * Error: * type: object * properties: * error: { type: string, example: Stok tidak cukup } * /orders: * post: * tags: [Orders] * summary: Buat pesanan baru * description: Memanggil product-service untuk mengurangi stok, lalu menyimpan pesanan. * requestBody: * required: true * content: * application/json: * schema: { $ref: '#/components/schemas/OrderRequest' } * responses: * 201: * description: Pesanan dibuat * content: * application/json: * schema: { $ref: '#/components/schemas/Order' } * 400: { description: Input tidak valid, content: { application/json: { schema: { $ref: '#/components/schemas/Error' } } } } * 404: { description: Produk tidak ditemukan, content: { application/json: { schema: { $ref: '#/components/schemas/Error' } } } } * 409: { description: Stok tidak cukup, content: { application/json: { schema: { $ref: '#/components/schemas/Error' } } } } * 503: { description: product-service tidak tersedia, content: { application/json: { schema: { $ref: '#/components/schemas/Error' } } } } * get: * tags: [Orders] * summary: Daftar semua pesanan * responses: * 200: * description: Berhasil * content: * application/json: * schema: * type: array * items: { $ref: '#/components/schemas/Order' } */

Restart dan buka http://localhost:3001/docs.

03

Gabungkan Dokumentasi di Gateway

cd ../gateway npm install swagger-ui-express

Pada gateway.js, tambahkan kode berikut sebelum middleware proxy (rute /product-service dan /order-service), supaya /docs dan /openapi.json ditangani gateway sendiri:

const swaggerUi = require('swagger-ui-express'); const DOC_SOURCES = [ { prefix: '/product-service', url: process.env.PRODUCT_DOC_URL || 'http://localhost:3000/openapi.json' }, { prefix: '/order-service', url: process.env.ORDER_DOC_URL || 'http://localhost:3001/openapi.json' }, ]; async function buildSpec() { const merged = { openapi: '3.0.3', info: { title: 'Toko API (via Gateway)', version: '1.0.0' }, servers: [{ url: '/' }], // "Try it out" memakai alamat gateway paths: {}, components: { schemas: {} }, }; for (const s of DOC_SOURCES) { try { const spec = await fetch(s.url, { signal: AbortSignal.timeout(2000) }).then(r => r.json()); for (const [path, ops] of Object.entries(spec.paths || {})) merged.paths[s.prefix + path] = ops; Object.assign(merged.components.schemas, (spec.components || {}).schemas); } catch (e) { console.warn('dokumentasi gagal diambil dari', s.url); } } return merged; } app.get('/openapi.json', async (req, res) => res.json(await buildSpec())); app.use('/docs', swaggerUi.serve, swaggerUi.setup(null, { swaggerOptions: { url: '/openapi.json' } }));

Restart gateway dan buka http://localhost:8080/docs. Anda harus melihat dua grup (Products dan Orders) dengan path berawalan /product-service dan /order-service. Jika Anda mengaktifkan API key di gateway pada lab 08, endpoint ini ikut terkena aturannya; sesuaikan sesuai kebutuhan.

04

Uji dari Dokumentasi dan Bandingkan dengan Janji

Di http://localhost:8080/docs, gunakan tombol Try it out:

  • POST /order-service/orders dengan {"productId":1,"qty":2}: harus 201. Lanjutkan dengan GET /product-service/products/1 untuk memeriksa stok berkurang.
  • Ulangi dengan qty 999: harus 409, sama seperti yang didokumentasikan. Coba juga productId 99 (harus 404).
  • Matikan product-service, lalu kirim order: harus 503, sesuai dokumentasi.

Setiap status yang muncul harus ada di daftar respons endpoint tersebut. Status yang muncul tetapi tidak didokumentasikan adalah celah dokumentasi; catat bila ada.

05

Tangkap Dokumentasi yang Tidak Sinkron (Drift)

Pada product-service.js, tambahkan field category: 'Periferal' pada ketiga produk di array products (hanya kode, jangan ubah anotasi). Restart, lalu panggil GET /product-service/products lewat Try it out. Respons nyata memuat category, tetapi contoh dan skema di dokumentasi tidak. Itulah drift: dokumentasi menjanjikan sesuatu yang sudah tidak benar.

Perbaiki dengan menambahkan category: { type: string, example: Periferal } pada skema Product, restart, lalu muat ulang /docs. Catat mengapa pendekatan code-first mengurangi, tetapi tidak menghilangkan, risiko ini.

06

Validasi dan Impor ke Postman

  • Buka http://localhost:8080/openapi.json di browser, simpan sebagai openapi.json (Save as), lalu tempel isinya di editor.swagger.io. Tidak boleh ada error (peringatan boleh).
  • Di Postman: Import → pilih file openapi.json. Koleksi berisi seluruh endpoint tanpa perlu membuat satu per satu. Jalankan satu permintaan untuk memastikan berfungsi.
07

README, Commit & Bukti

Buat README.md di akar repository berisi: deskripsi singkat sistem, cara menjalankan tiap service (urutan dan port), alamat dokumentasi (:8080/docs), dan variabel environment yang dipakai. Simpan openapi.json hasil gateway di repository. Commit tanpa node_modules.

Kesalahan Umum
Masalah yang Sering Muncul
Swagger UI tampil tetapi daftar endpoint kosong (paths: {})

Komentar tidak diawali @openapi, atau apis: [__filename] tidak menunjuk file yang berisi anotasi.

YAMLException: bad indentation / can not read a block mapping

Indentasi YAML di dalam komentar salah atau memakai tab. Gunakan spasi dan jaga kelurusan di bawah * .

Cannot GET /docs di gateway

Rute /docs ditaruh setelah middleware proxy atau gateway belum di-restart. Letakkan sebelum proxy.

Gateway hanya menampilkan satu service

Service lainnya belum menyala, atau URL /openapi.json-nya salah. Lihat peringatan "dokumentasi gagal diambil" di log gateway.

Try it out: Failed to fetch

Buka dokumentasi lewat gateway (:8080/docs) dan pastikan servers pada spesifikasi gabungan bernilai /. Membuka dokumentasi dari alamat berbeda dengan server yang dipanggil memicu masalah CORS.

Could not resolve reference: #/components/schemas/...

Nama skema yang dirujuk tidak ada. Gabungan hanya membawa components.schemas, jadi jangan memakai components.responses atau parameters bersama.

Checklist Kesiapan
  • Setiap service menyajikan /openapi.json dan /docs sendiri
  • Gateway menyajikan satu /docs gabungan berisi endpoint kedua service
  • Pesanan berhasil dibuat lewat Try it out, dan kode 404, 409, 503 sesuai dokumentasi
  • Anda sudah melihat drift terjadi, lalu memperbaikinya
  • openapi.json lolos validasi dan berhasil diimpor ke Postman
  • README berisi cara menjalankan dan alamat dokumentasi
