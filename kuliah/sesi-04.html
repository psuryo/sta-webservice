SESI 04

REST Lanjutan: Richardson Maturity Model & HATEOAS

Mahasiswa sudah bisa membuat REST API dari Backend Programming — sesi ini mengangkat pemahaman itu ke level yang lebih matang: seberapa "RESTful" sebenarnya API yang selama ini dibuat?

Durasi 100 menit
Format Kuliah Tatap Muka
Prasyarat REST API dasar (Backend Programming)
Tujuan Pembelajaran
  • 01Mahasiswa mampu menjelaskan empat level Richardson Maturity Model (RMM) dan ciri masing-masing level.
  • 02Mahasiswa mampu menerapkan resource naming dan penggunaan HTTP method/status code yang tepat sesuai level RMM 2.
  • 03Mahasiswa mampu menjelaskan konsep HATEOAS dan bagaimana ia meningkatkan discoverability API.
  • 04Mahasiswa mampu mengevaluasi level kematangan REST API yang pernah mereka buat sendiri.
Materi — Richardson Maturity Model

Empat Level Kematangan REST

Banyak API disebut "REST API" padahal sebenarnya baru menyentuh level paling dasar. Richardson Maturity Model (diperkenalkan Leonard Richardson) membagi kematangan REST menjadi 4 level berikut:

Level 0 — The Swamp of POX

Satu endpoint untuk segalanya

Semua request dikirim ke satu URL (mis. /api) lewat POST, dengan aksi ditentukan di dalam body. Mirip cara kerja SOAP — HTTP hanya dipakai sebagai "pipa", bukan dimanfaatkan semantiknya.

Level 1 — Resources

Mulai ada banyak endpoint

URL sudah dipecah per resource (mis. /users, /orders), tapi biasanya masih memakai satu HTTP method saja (umumnya POST) untuk semua operasi pada resource tersebut.

Level 2 — HTTP Verbs

Memanfaatkan HTTP secara semantik

GET, POST, PUT, DELETE dipakai sesuai maknanya masing-masing, dan status code HTTP (200, 201, 404, dst) dipakai secara tepat untuk merepresentasikan hasil operasi. Sebagian besar API "REST" di industri berhenti di level ini — termasuk kemungkinan besar API yang pernah dibuat di Backend Programming.

Level 3 — HATEOAS

API yang menuntun dirinya sendiri

Response tidak hanya berisi data, tapi juga link ke aksi/resource terkait yang bisa dilakukan selanjutnya — klien tidak perlu menghafal struktur URL di luar entry point awal.

Materi — HATEOAS

Hypermedia as the Engine of Application State

Alih-alih hanya mengembalikan data mentah, response API level 3 menyertakan link navigasi (biasanya di bagian _links) yang memberi tahu klien apa saja yang bisa dilakukan selanjutnya:

{ "id": 42, "status": "pending", "_links": { "self": { "href": "/orders/42" }, "cancel": { "href": "/orders/42/cancel", "method": "POST" }, "pay": { "href": "/orders/42/pay", "method": "POST" } } }

Perhatikan: klien tahu bahwa order berstatus "pending" bisa di-cancel atau dibayar, cukup dari melihat response ini — tanpa harus membaca dokumentasi terpisah atau menghafal pola URL.

Materi — Mengapa Level 3 Jarang Dipakai

Trade-off Kematangan REST

AspekLevel 2 (HTTP Verbs)Level 3 (HATEOAS)
Kompleksitas implementasiRendah — cukup familiar bagi kebanyakan developerLebih tinggi — perlu merancang struktur link secara konsisten
Coupling klien-serverKlien perlu menghafal struktur URL dari dokumentasiKlien mengikuti link dari response, lebih tahan perubahan URL
Adopsi industriSangat umum, hampir jadi standar de facto "REST API"Jarang diterapkan penuh, meski prinsipnya dipakai sebagian (mis. pagination link)

Level 2 sudah lebih dari cukup untuk sebagian besar kebutuhan — memahami level 3 penting bukan supaya semua API harus HATEOAS, tapi supaya sadar bahwa "REST" punya spektrum kematangan, dan bisa memilih level yang sesuai kebutuhan proyek.

Diskusi Kelas
Studi Kasus

Ambil salah satu API yang pernah Anda buat di mata kuliah Backend Programming. Diskusikan bersama teman sebangku: ada di level berapa API tersebut menurut Richardson Maturity Model? Apa satu perubahan kecil yang bisa menaikkannya ke level berikutnya?

Rangkuman
  • Richardson Maturity Model membagi kematangan REST menjadi 4 level: dari satu endpoint untuk segalanya (Level 0) hingga API yang menuntun dirinya sendiri lewat hypermedia (Level 3).
  • Sebagian besar API di industri, termasuk yang pernah dibuat di Backend Programming, kemungkinan besar berhenti di Level 2 — dan itu wajar, bukan berarti salah.
  • HATEOAS (Level 3) mengurangi coupling antara klien dan server dengan menyertakan link navigasi di dalam response.
  • Memilih level RMM yang tepat adalah soal trade-off kompleksitas vs fleksibilitas, bukan soal "semakin tinggi semakin baik" secara mutlak.
Tugas & Latihan
Latihan Mandiri

Pilih satu endpoint dari API yang pernah Anda buat (atau API demo mana pun yang familiar). Tuliskan: (1) level RMM endpoint tersebut saat ini beserta alasannya, dan (2) contoh response JSON yang sudah direvisi menambahkan minimal 2 link _links untuk menaikkannya ke Level 3.
